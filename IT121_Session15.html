Concept 1 · Modules 23.1–23.3

Network Security Testing

Test your defenses on purpose, before someone else tests them for you.

Security assessments and operations security

Network security testing checks whether security controls actually work. It's part of operations security: the day-to-day work of maintaining the network's security once it's in place, which is the usual responsibility of a new member of a security operations team. Testing happens during system implementation and in regular checks afterward. An assessment often starts with the basic commands every analyst should know:

CommandGathers
ipconfig / ip aThe host's own IP configuration (Windows / Linux)
pingWhether a host is reachable
tracert / tracerouteThe path packets take to a destination
nslookupDNS name and address lookups
netstatActive connections and listening ports on the host
arp -aThe ARP cache: IP-to-MAC mappings on the local segment
nbtstatWindows NetBIOS name resolution, for troubleshooting NetBIOS problems

Testing techniques

Network scanningFinds live hosts and open TCP and UDP ports. Every open port is a possible target.
Vulnerability scanningChecks for default passwords, missing patches, open ports, misconfigurations, and active IP addresses. A credentialed scan logs in to each host, so it gathers more information and gives fewer false positives and false negatives.
Password crackingTests whether users' passwords are weak enough to be guessed.
Log reviewChecks logs for signs of problems and for compliance.
Integrity checkersDetect changes to critical files and configurations.
Penetration testingSimulates a real attack to see how far an attacker could get. Covered in the next section.

Larger SOCs also use security orchestration, automation, and response (SOAR): platforms that automatically collect threat data from many sources and respond to routine, low-level events without a human, so analysts can focus on the rest.

Testing tools

ToolUsed for
Nmap / ZenmapA low-level network scanner (Zenmap is its GUI). Finds hosts, open ports, services, and operating systems. Can use decoy hosts to hide where a scan really comes from
SuperScanA Windows port-scanning tool
NessusA vulnerability scanner
TripwireAssesses and validates IT configurations against internal policies, best practices, and compliance standards
L0phtcrackPassword auditing and recovery
MetasploitA penetration testing framework for developing and running exploit code against a target
SIEMReal-time reporting and long-term analysis of security events. In testing, it shows the details of the source of suspicious activity

Concept 2 · Module 23.4

Penetration Testing

Hire someone to attack you, with permission and rules, and learn where you'd really break.

A penetration test (pen test) uses real attackers' techniques, in a controlled and authorized way, to see how the organization's systems and people respond. It's done by hired testers, sometimes former attackers, under a written agreement that sets the scope (what may be tested) and the rules of engagement (how and when). Testing without that permission is a crime.

The four phases

1 · PlanningAgree on goals, scope, rules of engagement, and timing.
2 · DiscoveryReconnaissance. Passive recon gathers information without touching the target: public websites, social media, leaked credentials. Active recon interacts with the target directly, such as scanning its ports.
3 · AttackTry to exploit what discovery found, gain access, and see how far it goes.
4 · ReportingDocument what was found, how, the risk each finding poses, and how to fix it.

How much the testers know

Black boxTesters start with no inside knowledge, like an outside attacker.
Gray boxTesters get some information, such as a user account or network diagram.
White boxTesters get full knowledge, such as source code and configurations, for the most thorough test.

A red team exercise takes this further: a team plays a realistic adversary over a longer period, often testing detection and response as well as defenses. The defenders are the blue team.

Pen tests and red teams as ways to evaluate controls are in Session 13.

Concept 3 · Modules 24.1–24.2

Threat Intelligence

No SOC sees every threat first. Threat intelligence is how defenders share what they've learned.

Information sources

SANSTraining and research. Runs the Internet Storm Center, a free early-warning system for internet threats.
MITREMaintains the CVE list and the ATT&CK knowledge base of attacker behavior.
FIRSTForum of Incident Response and Security Teams. Helps incident response teams around the world collaborate, share information, and react quickly.
ISC2Vendor-neutral education and career services, and certifications such as the CISSP.
CISCenter for Internet Security. Through MS-ISAC, provides 24x7 threat warnings, advisories, and incident response help to state, local, tribal, and territorial (SLTT) governments.
Vendor reports, blogs, podcastsSecurity vendors such as Cisco publish annual threat reports. Security news sites, blogs, and podcasts keep analysts current.

Threat intelligence services and standards

Service or standardWhat it does
Cisco TalosOne of the largest commercial threat intelligence teams. Collects information about active, existing, and emerging threats, and feeds it to Cisco security products
FireEyeDetects and blocks zero-day attacks with a signature-less engine that analyzes attacks statefully across every stage of their life cycle
AISThe U.S. Department of Homeland Security's free Automated Indicator Sharing: real-time exchange of threat indicators, such as malicious IP addresses and phishing senders, between government and private organizations
CVECommon Vulnerabilities and Exposures, maintained by MITRE: a dictionary giving each publicly known vulnerability a standard ID, such as CVE-2014-0160
STIXStructured Threat Information Expression: a standard format for describing threat information so it can be shared
TAXIITrusted Automated Exchange of Indicator Information: the protocol, over HTTPS, for exchanging STIX data
CybOXCyber Observable Expression: a standard for describing observable network events, now folded into STIX
Threat intelligence platform (TIP)Gathers threat data from many feeds into one place and presents it in a usable form

Shared intelligence often takes the form of indicators of compromise (IOCs): concrete evidence of an attack, such as malicious IP addresses, domains, file hashes, or unusual registry changes. A SOC can load IOCs into its SIEM and IDS, and search archived data for them, the retrospective analysis from Session 13.

Concept 4 · Module 25.1

Network and Server Profiling

You can't spot abnormal until you know what normal looks like.

A network baseline describes normal network behavior, so deviations stand out. Building one is part of the discovery step of vulnerability management. A network profile includes:

Session durationThe time between the start of a data flow and its end
Total throughputThe amount of data passing between hosts in a given period
Ports usedThe TCP and UDP processes available to accept data
Critical asset address spaceThe IP addresses of critical assets

A server profile sets the accepted operating parameters for a server:

Listening portsThe TCP and UDP daemons and ports that are allowed to be open
User accountsThe parameters defining user access and behavior
Service accountsThe type of service an application is allowed to run
Software environmentThe tasks, processes, and applications permitted to run on the server

Testing for vulnerabilities

TestPurpose
Risk analysisEvaluates the risk posed by vulnerabilities to a specific organization: likelihood of attack, likely threat actors, and the consequences of a successful exploit
Vulnerability assessmentUses software to scan servers and find known vulnerabilities
Penetration testingUses authorized simulated attacks to test the strength of network security

Concept 5 · Module 25.2

Common Vulnerability Scoring System (CVSS)

One number from 0 to 10 that tells everyone how bad a vulnerability is, and the metrics that explain why.

The Common Vulnerability Scoring System (CVSS) is a vendor-neutral, industry-standard way to rate the severity of vulnerabilities. A CVSS score is built from three metric groups:

Base metric groupThe characteristics of the vulnerability itself, which don't change over time or between environments. Split into Exploitability metrics and Impact metrics.
Temporal metric groupCharacteristics that change over time, such as whether exploit code is available or a patch has been released.
Environmental metric groupAdjusts the score for a specific organization's environment, such as how important the affected system is to it.

Base metrics

MetricAsks
Attack vector (AV)How close the attacker must be: network, adjacent network, local, or physical. The farther away an attacker can be, the higher the score
Attack complexity (AC)Conditions beyond the attacker's control that must exist for the exploit to work
Privileges required (PR)The level of access the attacker needs first: none, low, or high
User interaction (UI)Whether a user other than the attacker must take part, such as clicking a link
Scope (S)Whether the exploit can affect components beyond the vulnerable one
Impact: C, I, AThe effect on confidentiality, integrity, and availability: none, low, or high

Severity ratings

ScoreRating
0.0None
0.1 – 3.9Low
4.0 – 6.9Medium
7.0 – 8.9High
9.0 – 10.0Critical

CVSS reports usually appear with a vector string, a compact summary of every metric value, such as AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H (network attack, low complexity, no privileges, no user interaction, high impact on all three: a 9.8 Critical). The U.S. National Vulnerability Database (NVD) publishes CVSS scores for CVE entries.

Concept 6 · Module 25.3

Secure Device Management

Know every device you have, keep it configured correctly, and keep it patched.

Responding to vulnerability risk

Vulnerability management starts with threat-vulnerability (T-V) pairing: identifying threats and vulnerabilities, then matching each threat to the vulnerabilities it could exploit. Each pair is then handled with one of four strategies:

Risk avoidanceStop doing the activity that creates the risk.
Risk reductionReduce the vulnerability, for example by patching or adding a control.
Risk sharingShift part of the risk to someone else, such as an insurer or a cloud provider.
Risk retentionAccept the risk and its consequences, usually because it's small or costly to fix.

The vulnerability management life cycle

1 · DiscoverInventory all assets, build a network baseline, and identify vulnerabilities.
2 · Prioritize assetsGroup assets and assign each a business value.
3 · AssessBuild a baseline risk profile, based on asset value, threats, and vulnerabilities.
4 · ReportDocument the security risk level for each asset.
5 · RemediateFix vulnerabilities in order of risk.
6 · VerifyConfirm the fixes worked, through follow-up audits.

Managing devices

Asset managementTracking every hardware and software asset: where it is, who's responsible, and what's installed.
Mobile device management (MDM)Centrally enforcing security on phones and tablets, including company-owned and BYOD devices: encryption, PINs, remote wipe.
Configuration managementKeeping systems in known, approved configurations, and controlling changes.
Enterprise patch managementTesting and deploying updates across the organization. Done with agent-based tools on each host, agentless scanning, or passive network monitoring to spot unpatched systems.

Concept 7 · Modules 26.1–26.2

Risk Management and Risk Assessment

You can't remove all risk. You can measure it, and decide what to do about it.

Risk management

Risk is the probability of loss due to a threat. It combines how likely a threat is to exploit a vulnerability with how bad the impact would be. (A weakness itself is a vulnerability, not a risk.) Risk management is an ongoing four-step process:

1 · FrameIdentify threats across the organization and set the context: which risks matter, and how much risk the organization will tolerate.
2 · AssessDetermine how severe each identified risk is.
3 · RespondChoose and carry out an action for each risk.
4 · MonitorWatch for changes in risk and check that the responses keep working.

The four possible responses:

ResponseMeaningExample
AvoidanceStop the risky activity entirelyDon't store card numbers at all
Mitigation (reduction)Lower the likelihood or impact with controlsAdd MFA and patching
TransferShift some of the risk to a third partyBuy cyber insurance
AcceptanceKnowingly accept it, because it's small or fixing it costs more than it savesLeave a low-value test server as is

Calculating risk: quantitative analysis

Quantitative risk analysis assigns money values, which works for assets with a measurable value, such as items in an equipment database.

TermMeaning
Asset value (AV)What the asset is worth
Exposure factor (EF)The percentage of the asset's value lost in one incident
Single loss expectancy (SLE)SLE = AV × EF: the expected loss from one incident
Annualized rate of occurrence (ARO)How many times a year the incident is expected (0.25 means once every four years)
Annualized loss expectancy (ALE)ALE = SLE × ARO: the expected loss per year

The ALE tells you how much a control is worth. A control that costs less per year than the loss it prevents is usually justified.

Qualitative analysis

Qualitative risk analysis uses ratings such as low, medium, and high instead of dollar figures. It's based on opinions, scenarios, and past events, such as earlier break-in attempts, and usually places each risk on a likelihood × impact matrix. It's faster and works for things that are hard to price, such as reputation, but it's less precise.

Concept 8 · Module 26.3

Security Controls

Controls are classified by what they do, and when, relative to an incident.

PreventiveStop an incident before it happens. Examples: firewalls, locks, MFA.
DeterrentDiscourage someone from trying. Examples: a login warning banner listing the consequences of misuse, visible cameras.
DetectiveIdentify an incident while or after it happens. Examples: IDS, log review, motion sensors.
CorrectiveAct after a violation to fix the problem and restore the system to its normal state. Examples: quarantining malware, patching the exploited flaw.
RecoveryRestore resources and capabilities after a violation. Examples: backups and restores, fault-tolerant storage.
CompensativeAn alternative used when the main control isn't possible or too costly. Example: extra monitoring for a legacy system that can't be patched.

Corrective and recovery controls both work after a policy violation. Controls are also grouped by how they're implemented: administrative (policies, training), technical (firewalls, encryption), and physical (locks, guards). Choosing controls depends on the organization: its risk assessment results, budget, regulations, and how much risk it accepts.

Concept 9 · Module 27.1

Evidence Handling and Attack Attribution

Digital forensics recovers and investigates material found on digital devices, in a way that holds up in court.

The forensic process

NIST describes four steps (in Special Publication 800-86):

1 · CollectionIdentify and gather possible sources of data, while protecting their integrity.
2 · ExaminationExtract the relevant information from the collected data. That may mean decompressing or decrypting it, and filtering out what isn't relevant.
3 · AnalysisDraw conclusions from the data, linking people, places, times, and events.
4 · ReportingPresent the findings, how they were reached, and recommendations.

Types of evidence

Best evidenceEvidence in its original state, such as the actual storage device used by the accused.
Corroborating evidenceEvidence that supports another piece of evidence.
Indirect evidenceAlso called circumstantial. Combined with other facts, it suggests a conclusion.

Order of volatility

Some evidence disappears the moment a computer is turned off. Collect the most volatile data first:

OrderSource
1CPU registers and cache
2Routing table, ARP cache, process table, kernel statistics, RAM
3Temporary file systems
4Non-volatile storage, such as hard drives
5Remote logging and monitoring data
6Physical interconnections and topology
7Archival media, such as backup tapes

The order trips people up, because the most important-sounding evidence, the hard drive, comes after things that seem trivial. The reason is about time, not importance, and the castle town had a version of it every winter.

Think of it like… tracks in the snow A thief climbs the castle wall on a snowy night. By morning the magistrate's investigator has many clues: footprints in the fresh snow, a scrap of cloth on a nail, scratches in the stone, and the gate log. The footprints go first. They melt by noon, so they're sketched before anything else, even though the stone scratches might matter more. The cloth can wait an hour. The scratches and the log will still be there next month. That's the order of volatility: memory and network state are footprints in snow; the hard drive and the backup tapes are scratches in stone.

Chain of custody and integrity

Chain of custody is the documented record of who collected, handled, and stored evidence, when, and where, from collection to the courtroom. A gap lets the defense argue the evidence was tampered with. To preserve integrity, investigators work on a copy, never the original, use write blockers so the original can't be changed, and record a hash of the evidence at collection so they can prove later that the copy is identical.

Attack attribution

Attack attribution means identifying who is responsible for an attack. Investigators look at the threat actor's techniques, tools, and infrastructure, compare IOCs with threat intelligence, validate whether the attacker's IP address is genuine or spoofed, and search incident databases and the internet for related attacks. MITRE ATT&CK helps here: it's a global knowledge base of threat actor tactics, techniques, and procedures (TTPs), built from real-world observations.

Concept 10 · Module 27.2

The Cyber Kill Chain

Seven steps every attacker must complete. Break any one, and the attack fails.

Developed by Lockheed Martin, the Cyber Kill Chain identifies the steps an adversary must complete to reach their goal. Defenders use it to see where in an attack they are, and where they could have stopped it.

StepAttackerDefender
1. ReconnaissanceResearches the target: websites, employees on social media, scans for open portsWatch for scans and unusual browsing of public sites. Limit what's published
2. WeaponizationPairs an exploit with a payload, such as malware in a document, ready to launch against a vulnerability it foundKeep up with threat intelligence about new exploits and malware
3. DeliverySends the weapon: phishing email, malicious website, USB driveEmail and web filtering, user training, blocking removable media
4. ExploitationThe exploit runs and takes advantage of the vulnerabilityPatching, hardening, endpoint protection
5. InstallationInstalls a backdoor or remote access tool to stay inHIDS, application allow-listing, file integrity monitoring
6. Command and control (C2)Opens a channel to its CnC server to control the compromised hostBlock known CnC domains, watch DNS and outbound traffic
7. Actions on objectivesAchieves the goal: steal data, encrypt it for ransom, launch a DDoS, move to other hostsDetect data exfiltration, incident response, recovery

The chain describes a digital attack, but the logic of it is very old. Any castle guard who studied how infiltrators worked knew the steps.

Think of it like… a shinobi's mission against the castle A shinobi sent against a castle first watches it for days: guard changes, weak walls, which servants go to market (reconnaissance). He prepares his tools and a merchant's disguise to fit what he saw (weaponization). He walks in with a delivery of charcoal (delivery), slips through the unlocked postern he spotted (exploitation), and hides a rope at the wall for later (installation). He sets up a way to pass messages to his lord outside (command and control), and finally steals the plans or opens the gate at night (actions on objectives). Spot him at the market, turn away the charcoal cart, or find the rope, and the mission fails. The earlier, the better.

Concept 11 · Module 27.3

The Diamond Model of Intrusion Analysis

Every intrusion event has four parts. Find one, and you can pivot to the others.

The Diamond Model describes each intrusion event with four core features, the corners of a diamond:

  • Adversary: the party responsible for the intrusion.
  • Capability: the tool or technique the adversary uses against the victim, such as malware or an exploit.
  • Infrastructure: the physical or logical communication the adversary uses to deliver the capability and stay in control, such as IP addresses, domains, and email accounts.
  • Victim: the target of the attack, whether a person, organization, system, or network.

The model's power is pivoting: from a known piece, follow the edges to discover the others. Knowing the malware (capability) leads to its CnC domain (infrastructure), which leads to other victims and maybe the adversary.

Meta-features

Each event also records meta-features:

TimestampWhen the event started and stopped
PhaseWhere it fits in a chain of steps, such as a Kill Chain step
ResultThe outcome: success, failure, or unknown, and its effect on confidentiality, integrity, and availability
DirectionWhich way the event moved, such as adversary-to-infrastructure or infrastructure-to-victim
MethodologyThe general class of activity, such as phishing or a port scan
ResourcesWhat the adversary used: software, knowledge, usernames and passwords, funding, or facilities

Linking events in time order creates an activity thread, the attack's story. The Diamond Model and the Kill Chain fit together: each event in the thread sits in one Kill Chain phase.

Concept 12 · Module 27.4

Incident Response

NIST Special Publication 800-61r2 is the standard playbook for handling a security incident.

Establishing a CSIRC

NIST recommends that an organization set up a computer security incident response capability (CSIRC), built from three elements:

PolicyDetails how incidents should be handled based on the organization's mission, size, and functions. Includes management's commitment, purpose and scope, definitions, organizational structure and authority, and severity ratings.
PlanThe roadmap for putting the policy into practice: strategy and goals, how the team communicates with the rest of the organization, and metrics for measuring how well incident response works.
ProceduresDetailed, technical step-by-step instructions the team follows during an incident.

Incident response involves many stakeholders beyond IT: management, legal, human resources, public relations, physical security, and sometimes law enforcement.

The NIST incident response life cycle

1 · PreparationBuild the CSIRC, train the team, gather tools, and put preventive controls in place before anything happens.
2 · Detection and AnalysisSpot signs of an incident from alerts, logs, and reports. Analyze them, decide whether it's real, document it, and set its priority.
3 · Containment, Eradication, and RecoveryStop the spread, remove the threat, and restore systems to normal operation.
4 · Post-Incident ActivityHold a lessons-learned review, keep the evidence, and improve preparation for next time.

Inside the phases

  • Detection and analysis uses precursors (signs an incident may happen soon, such as a scan or a threat announcement) and indicators (signs one has happened or is happening, such as an IDS alert or a strange login).
  • Containment strategies depend on the incident: disconnecting a host, blocking an address, disabling an account. Evidence is gathered with chain of custody while containing.
  • Eradication after malware: restore systems from clean, recent backups; update and patch the OS and software on all hosts; rebuild hosts from installation media if there's no clean backup; and change passwords on affected accounts and devices.
  • Post-incident activity asks what happened, how well the team did, what should change, and what precursors or indicators to watch for next time. Incidents may also need to be reported to authorities, customers, or regulators.

Concept 13 · Module 27.5

Disaster Recovery

Some events take whole systems down: fire, flood, or ransomware. Plan the way back before you need it.

Types of disasters

NaturalGeological (earthquakes, tsunamis), meteorological (floods, storms), health (pandemics), and others such as fires.
Human-causedLabor events such as strikes, social or political events such as vandalism and sabotage, materials such as hazardous spills, and utility disruptions such as power outages. Cyberattacks belong here too.

Planning

A disaster recovery plan (DRP) covers how to restore IT systems and data after a disaster. To write one, management has to answer questions about each critical process: what the process is, who is responsible for it, where it's performed, and why it's critical. A business continuity plan (BCP) is broader: it covers keeping the whole business running, including moving critical systems to another location and succession planning for key people. The DRP is part of the BCP.

Backups and restores

Full backupCopies everything. Slowest to make, simplest to restore.
Incremental backupCopies only what changed since the last backup of any kind. Fast to make, but a restore needs the full backup plus every incremental after it.
Differential backupCopies everything changed since the last full backup. A restore needs only the full backup plus the latest differential.

Backups must be stored off the device, and ideally offsite or offline, so a fire or ransomware doesn't destroy them along with the original. They must also be tested. A backup that has never been restored isn't proven to work. Network devices need backing up too. On a Cisco router, the configuration can be copied to a TFTP server and restored the same way:

R1# copy running-config tftp:
R1# copy tftp: running-config

On Linux, tar archives files and rsync copies them efficiently to another system. Windows has built-in File History and backup tools.

Risk calculation

Is the backup generator worth it?

Kaidō Freight's dispatch server is worth $80,000. A regional power outage would damage about 25% of its value, through lost data and hardware damage. Outages like that are expected about once every two years. A generator and UPS would cost $7,500 a year. Calculate the ALE, and decide whether the control is justified.

Show answer

SLE = AV × EF = $80,000 × 0.25 = $20,000.

ARO = once every two years = 0.5.

ALE = SLE × ARO = $20,000 × 0.5 = $10,000 per year.

The control costs $7,500 a year and prevents an expected $10,000 a year of loss, so it's justified, assuming it prevents most of the loss. This is risk mitigation.

CVSS

Which patch first?

Kiriyama General Hospital's vulnerability scan finds two issues. (A) A flaw in the public web server: AV:N/AC:L/PR:N/UI:N, high impact on C, I, and A, score 9.8. (B) A flaw on an internal kiosk: AV:P/AC:L/PR:N/UI:R, high confidentiality impact only, score 4.3. Which is more urgent, and what do the attack vectors tell you?

Show answer

A is Critical (9.8) and B is Medium (4.3). Patch A first.

A's attack vector is Network (N): anyone on the internet can try it, with no privileges and no user interaction. B's is Physical (P): the attacker must touch the kiosk, and a user must take part (UI:R). The farther away an attacker can be, the higher the score. The environmental metrics could still raise B if that kiosk handles especially sensitive patient data.

Kill Chain

Mapping the Tsukimi incident

Put these events from a Tsukimi Sweets incident in Kill Chain order, and name each step: (a) the bookkeeper opens an "invoice" attachment; (b) the attacker reads Tsukimi's website and LinkedIn to learn who pays the bills; (c) a macro in the document exploits an unpatched spreadsheet program; (d) the attacker builds a malicious invoice document; (e) the infected PC starts beaconing to an unfamiliar domain; (f) a remote access tool is installed to survive reboots; (g) customer card data is copied out.

Show answer

(b) Reconnaissance → (d) Weaponization → (a) Delivery → (c) Exploitation → (f) Installation → (e) Command and control → (g) Actions on objectives.

The cheapest break points: training the bookkeeper (delivery), patching the spreadsheet program (exploitation), or DNS filtering that blocks the beacon (C2) before any data leaves.

Diamond Model

Filling in the diamond

Using the same Tsukimi incident, assign each item to a Diamond Model feature: the bookkeeper's PC; the malicious macro and remote access tool; the beaconing domain and the email account that sent the invoice; a criminal group that threat intelligence links to that domain. Then name one pivot.

Show answer

Victim: the bookkeeper's PC (and Tsukimi Sweets). Capability: the macro and the remote access tool. Infrastructure: the domain and the sending email account. Adversary: the criminal group.

Pivot: from the infrastructure (the domain) to other victims. Search Bastion's DNS logs for every client host that contacted it. Kaidō Freight or Kiriyama might be compromised too.

Forensics

What to collect first

A Kiriyama workstation is suspected of running memory-only malware. It's still powered on. A technician wants to shut it down and pull the hard drive. What should the responder do instead, and in what order?

Show answer

Don't power it off first. Memory-only malware lives in RAM, which is erased at shutdown. Follow the order of volatility: capture memory and live system state (running processes, network connections, ARP and routing tables) first, then temporary files, then image the hard drive with a write blocker, then gather remote logs.

Hash each image at collection, work only from copies, and record every handoff on the chain of custody form.

Incident response

Which phase is this?

Name the NIST incident response phase for each Bastion activity: (a) running a tabletop exercise with Kaidō Freight's managers; (b) deciding whether a cluster of failed-login alerts is a real attack; (c) disconnecting an infected PC from the network; (d) rebuilding the PC from installation media and patching it; (e) a meeting a week later about why the attack wasn't detected sooner.

Show answer

(a) Preparation. (b) Detection and Analysis. (c) and (d) Containment, Eradication, and Recovery: (c) is containment, and (d) is eradication and recovery. (e) Post-Incident Activity, the lessons learned, which feeds back into preparation.

Security controls

Name the control type

Classify each: (a) a login banner warning that misuse will be prosecuted; (b) nightly backups and fault-tolerant RAID storage; (c) the IDS; (d) the firewall; (e) quarantining a malware file after detection; (f) extra monitoring on an old machine that can't be patched.

Show answer

(a) Deterrent. (b) Recovery. (c) Detective. (d) Preventive. (e) Corrective. (f) Compensative. Corrective and recovery both act after a violation.
