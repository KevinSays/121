Concept 1 · Module 12.1

Physical Security

If someone can walk up to the server, most other defenses stop mattering. Physical security keeps people away from the equipment, and records who got close.

Fencing and physical barriers

Barriers are usually the outermost and most visible layer. They include perimeter fences, security gates, bollards (short posts that stop vehicles), vehicle entry barriers, and guard shelters. Fence height decides who it stops:

HeightWhat it does
1 m (3–4 ft)Deters casual trespassers only
2 m (6–7 ft)Too high for a casual trespasser to climb
2.5 m (8 ft)Offers limited delay to a determined intruder

High-security areas add a top guard, like barbed or concertina wire. Fences need regular maintenance, local rules may limit what you can build, and vehicles should never park next to one, since a car roof makes a good ladder.

Biometrics

Biometrics are a person's physiological or behavioral characteristics: face, fingerprint, hand geometry, iris, retina, signature, or voice. When choosing a biometric system, weigh accuracy, speed, user acceptance, uniqueness, resistance to counterfeiting, reliability, storage needs, enrollment time, and how intrusive the scan is. Accuracy matters most, and it's measured by error type:

ErrorWhat happensWhy it matters
Type I: false rejectionA legitimate user is turned awayAnnoying and costly, like a lost sale at a checkout
Type II: false acceptanceAn impostor is let inA security breach. Usually treated as the most important error
Crossover error rate (CER)The point where the false rejection rate equals the false acceptance rateThe usual single measure of a system's overall accuracy. Lower is better

Surveillance, guards, and RFID

ControlStrengthsWeaknesses
Video and electronic surveillanceWatches areas when nobody is there, records for long periods, links to motion detection and alerts. In high-security sites, cover every entrance, exit, loading bay, stairwell, and refuse areaSomeone still has to respond
Guards and escortsRespond instantly, adapt to new situations, and make decisions on the spotCost, limited ability to track high volumes of traffic, human error
RFID asset tagsReaders hidden in door frames flag any tagged asset that leaves a secure area. Reads many tags at once, with no line of sight and no visible tag neededOnly tracks what's tagged

Concept 2 · Module 12.2

Application Security

Applications are where users and data meet, so they're a favorite target. Security has to be built in while the software is written, not bolted on after.

The development process

StageWhat happens
Developing and testingCode is written, tested, and debugged in a development environment, which is less restricted than production. Version control tracks changes, sandboxes keep work from being overwritten, and quality assurance (QA) finds defects
Staging and productionStaging closely matches production, so developers can confirm the software runs under the real security settings before it's deployed
Provisioning and deprovisioningCreating or updating software, and removing it. A self-service portal can automate both

Secure coding techniques

TechniqueWhat it does
NormalizationConverts input to its simplest known form, so each string has one representation and malicious input stands out. Also organizes database data to protect integrity
Stored procedureA group of precompiled SQL statements kept in the database. It takes input as parameters, which cuts traffic and speeds results
Obfuscation and camouflageObfuscation hides data with random characters. Camouflage swaps it for realistic fake data. Both make reverse engineering harder
Code reuseBuilding on existing software saves time and money, but can carry old vulnerabilities in with it
SDKs and third-party librariesReady-made code that speeds development. A flaw in one library can affect every application that uses it

Input validation

Many attacks work by feeding an application malformed data, to confuse it, crash it, or make it reveal too much. NetAcad's example: a newsletter sends confirmation links, attackers alter the links to change usernames, emails, or subscription status, then automate it to flood the database with thousands of fake subscribers. A validation rule checks that data falls inside the limits the database designer set:

CheckWhat it tests
SizeThe number of characters
FormatThat data matches the required format
ConsistencyThat codes in related data items agree
RangeThat a value is between a minimum and a maximum
Check digitAn extra calculated digit that detects errors

Integrity checks

An integrity check uses a hash function to take a snapshot of data, then compares later snapshots to confirm nothing changed. A checksum is one example: the sender and receiver each compute a value, and if the two match, the data arrived intact. Common hash functions are MD5, SHA-1, SHA-256, and SHA-512. Integrity is also protected by:

  • Version control: two users can't update the same file, record, or transaction at the same time
  • Backups: a verified, accurate backup restores corrupted data
  • Authorization: permissions on a need-to-know basis, such as setting a file to read-only

Other practices

Code signing digitally signs executables, which proves who wrote them and that the code hasn't changed since. Secure cookies are sent only over HTTPS, so the data they hold isn't exposed over plain HTTP.

Threat to applicationsHow to manage it
Unauthorized access to data centers, computer rooms, and wiring closetsPolicies, standards, and procedures for staff and visitors
Server and system downtimeBusiness continuity and disaster recovery plans for critical applications
OS and application vulnerabilitiesAn update policy, and regular patching
Unauthorized access to systemsMulti-factor authentication and log monitoring
Data lossData classification standards and backup procedures
Software development vulnerabilitiesTesting before launch

Concept 3 · Module 12.3

Network Hardening: Services and Protocols

Every running service is a door. Hardening means closing the doors you don't need and locking the ones you keep.

Start by finding the doors. A port scanner sends a message to each port and reads the response, which shows whether the port is open and what's using it. Attackers run the same scans, so you want to see the results first. The goal is that only necessary ports are exposed.

Network and routing services

ServiceWhat attackers doHow to harden it
DHCPTarget the server to deny devices their addresses, or run a rogue DHCP serverDHCP snooping blocks rogue servers. Also: physically secure the server, patch it, put it behind a firewall, review DHCP logs, run antivirus, remove unused services, and close unused ports
DNSTamper with name resolution (Session 3's DNS poisoning)DNSSEC adds digital signatures. Also: keep DNS software updated, hide the version string, separate internal and external DNS servers, restrict transactions by client IP, sign transactions and zones, limit zone transfers and dynamic updates, and log
ICMPUse it for reconnaissance, denial of service, and covert channelsMany networks filter ICMP requests
RIPAttack routers and routing updates to hurt performance or redirect trafficUse routing with authentication, and keep routers patched. (RIP picks routes by hop count, with a maximum of 15 hops)
NTPAttack time servers to break certificate-based communication and hide their tracksNTP authentication, so devices only trust a verified time server

Secure protocols

InsecureSecure replacementWhy
Telnet (TCP 23)SSH (TCP 22)Telnet sends usernames, passwords, and data in plaintext that anyone running Wireshark can read. SSH encrypts the whole session
Plain file copySCPUses SSH to transfer files with authentication and confidentiality
Older SNMP versionsSNMPv3The current standard. Uses cryptography to stop eavesdropping and detect tampering
HTTP (port 80)HTTPS (SSL/TLS)TLS is the updated, more secure replacement for SSL. It encrypts traffic between client and server
FTPFTPSFTP logs in with a plaintext username and password. FTPS adds SSL/TLS
POP (110) and IMAP (143)POP or IMAP over SSL/TLS, and S/MIMETLS encrypts mail in transit. S/MIME signs and encrypts messages, for authentication, integrity, and nonrepudiation
Think of it like… patrolling the walls A well-run castle doesn't wait for someone to shout before it checks the walls. Guards walk the walls on a schedule, looking for the side gate left unbarred or the stone that's come loose. A regular port scan is that patrol: you find the open door before a shinobi does. The patrol only works if you know which gates are supposed to exist, which is why Session 5's baseline comes first.

Concept 4 · Module 12.4

Network Hardening: Segmentation

A flat network lets an attacker who gets in reach everything. Segmentation splits it into pieces with controlled crossings between them.

VLANs

A virtual LAN (VLAN) groups devices logically, regardless of which switch they're physically plugged into. A LAN is defined by physical connections; a VLAN is defined by logical ones. Each switch port is assigned to a VLAN, and trunk ports carry traffic for several VLANs between switches. Devices in a VLAN act like their own network. That lets you put sensitive systems, like HR's, in a separate VLAN, and it limits broadcast traffic. Protect VLANs by monitoring them, using advanced configurations, and patching.

The DMZ and zones of risk

A demilitarized zone (DMZ) is a small network between the trusted private network and the internet. Web and mail servers go there, so outsiders can reach them without touching the internal network. Most networks have two to four zones:

ZoneRiskTrust
Private LANLowHigh
ExtranetMedium-lowMedium-high
DMZMedium-highMedium-low
InternetHighLow

Zero trust

Firewalls manage two directions of traffic. North-south traffic moves into and out of the organization's network. East-west traffic moves between servers inside the data center. Automatically trusting everyone inside lets an attacker who gets in move freely. The zero trust model monitors every user constantly, whatever their status or role. Concept 5 · Module 12.5

Hardening Wireless and Mobile Devices

Wireless signals leave the building and mobile devices leave with their owners. Both need protection that works outside your walls.

Wireless security standards

StandardWhat it added
WEPThe first wireless security protocol, with 64- or 128-bit keys. Broken
WPAThe response to WEP's weaknesses. 256-bit keys, message integrity checks (MIC) to detect altered data, and TKIP for better key handling. WPA-PSK (pre-shared key) is its most common setup. AES later replaced TKIP
WPA2Made AES mandatory and replaced TKIP with CCMP, an AES-based protocol
WPA3Builds on WPA2 with stronger cryptography and better key exchange
WPSConnects devices with a PIN. The PIN can be brute-forced, so disable WPS

Authentication

The original 802.11 standard had two methods. Open system authentication lets any device connect; use it only where security doesn't matter. Shared key authentication authenticates and encrypts between the client and the access point. For enterprise networks, EAP (Extensible Authentication Protocol) is the framework: the access point collects the user's ID and password and relays them to an authentication server, which approves or denies the connection.

EAP typeClient cert?Server cert?DeploymentSecurity
EAP-TLSYesYesDifficultHigh
PEAPNoYesModerateMedium
EAP-TTLSNoYesModerateMedium
EAP-FASTNoNoEasyMedium

A rogue access point is any unauthorized device that bridges wireless clients onto the network, often imitating a real one to steal data. Mutual authentication, where both sides authenticate each other before connecting, defeats it.

Mobile communication methods

MethodWhat it is
Wi-Fi and BluetoothWireless signals for network and short-range connections
Near-field communication (NFC)Contactless communication over a few centimeters, such as tap-to-pay
Infrared (IR)Short-range, line-of-sight communication, like a phone acting as a TV remote
USBThe only wired method. Used for storage, tethering, and connecting forensic acquisition devices during an investigation

Managing and protecting mobile devices

Company devices may be corporate-owned, or corporate-owned, personally enabled (COPE); others are BYOD. Mobile device management covers:

  • Storage segmentation and containerization: an authenticated, encrypted area that keeps work data apart from personal data. It can isolate apps, control what they do, delete the container, and remotely wipe the device
  • Content management: controlling what users can reach in data-sharing apps like Dropbox, Box, Google Drive, and iCloud
  • Application management: allow listing signed apps so users install only trusted ones, plus strong passwords for apps that need credentials

Threats include theft, loss, unauthorized access, and OS, application, and network risks. Users also bypass the device's own limits:

BypassWhat it does
JailbreakingRemoves Apple's restriction to approved apps
RootingBypasses Android's security architecture for full administrative access
SideloadingInstalls unapproved apps from outside the approved store. Less invasive, still a risk

Tools can detect jailbroken or rooted devices, mark them noncompliant, and cut their access. Safeguards include screen locks, biometric authentication, context-aware authentication (machine learning that judges access by the user's normal behavior), remote wiping, and full device encryption. GPS locates a device to within about 5 meters. Geolocation and geofencing drive location-based push notifications, which attackers have started using to capture data.

Concept 6 · Module 12.6

Cybersecurity Resilience

Availability is the "A" in CIA. Resilience is how you keep it when hardware fails, power drops, or an attack lands.

High availability

High availability describes systems designed to avoid downtime as much as possible. It rests on three design principles:

PrincipleHow
Eliminate single points of failureFind every component whose failure takes the whole system down, then add hot standby devices, redundant components, and multiple paths
Provide reliable crossoverRedundant power supplies, backup power, and backup communications that take over smoothly
Detect failures as they occurActive monitoring that spots failures, and can even trigger the backup system

A single point of failure can be hardware, a process, a piece of data, a utility, or even one highly skilled staff member. The fix is to stop relying on any single element.

The five nines

A popular availability goal is five nines: 99.999% uptime. Here's what each extra nine buys you:

AvailabilityMaximum downtime per year
99.9% (three nines)About 8.8 hours
99.99% (four nines)About 53 minutes
99.999% (five nines)About 5.26 minutes

Common steps toward it: standardized systems that use the same components, so parts are easy to stock and swap; clustering, where several devices appear to users as one, so one can fail without an outage; and shared component systems, where a whole system can stand in for one that failed.

Redundancy techniques

TechniqueWhat it does
N+1 redundancyEvery component (N) has at least one backup (+1), like a car's four tires and a spare. It survives losing one of each component, but it isn't a fully redundant system
RAIDSpreads data across several drives. Mirroring duplicates data on a second drive, striping spreads consecutive segments across drives, and parity adds checksums so lost data can be rebuilt. Every level except RAID 0 survives losing a disk. Hardware or software based
Spanning Tree Protocol (STP)Keeps redundant switch links loop-free by blocking extra paths, then unblocks one if the active link or switch fails
Router redundancyA standby router shares a virtual IP address with the forwarding router, and end devices use that virtual IP as their default gateway. If the standby stops hearing the forwarding router's periodic messages, it takes over. This is first-hop redundancy

Location redundancy

ReplicationTimingTrade-off
SynchronousBoth sites updated in real timeNeeds high bandwidth, and the sites must be close together to keep latency low
AsynchronousNearly real timeLess bandwidth, and the sites can be farther apart
Point-in-timeThe backup site is updated periodicallyThe most bandwidth-friendly, since no constant connection is needed

Resilient design

Resiliency is the methods and configurations that make a system tolerate failure. Redundant links with STP, and well-tuned routing protocols, switch over fast enough that users don't notice. Application resilience is an application's ability to keep working through component problems, using fault-tolerant hardware (multiples of every critical component in one computer), a cluster architecture, or backup and restore. Cisco IOS resilient configuration keeps a secure copy of the router's IOS image and running configuration (the primary bootset) that users can't delete, for fast recovery if flash or the startup config is erased.

Fault tolerance keeps a system running when components fail; data mirroring is an example. System resiliency goes further: data and services stay available even during an attack, which takes redundant power and processing.

Backups

Backups are one of the best protections against data loss, and a sound security policy requires them, usually stored off-site. Plan for:

  • Frequency: a full backup weekly or monthly plus frequent partial backups. More partial backups means a longer restore
  • Storage: rotate backups to an approved off-site location on the schedule the policy sets
  • Security: password-protect backups
  • Validation: always validate backups to confirm the data's integrity

Power and HVAC

Data centers should have their own power supply, two or more feeds from different substations, power conditioning, backup power, and a UPS (uninterruptible power supply) to shut systems down gracefully.

CategoryMomentaryProlonged
Power excessSpike: high voltageSurge: high voltage
Power lossFault: loss of powerBlackout: complete loss of power
Power degradationSag or dip: low voltageBrownout: low voltage

An inrush current is the initial surge of power when equipment switches on. HVAC systems control temperature, humidity, and airflow to match the hardware's environmental requirements, found in its product specifications. Modern HVAC systems connect to the internet for remote management by contractors, which spreads access to many people and makes the system a security risk of its own.

Other measures for physical facilities: access control and CCTV at every entrance, visitor policies, building security testing (digital and physical), encrypted entry badges, disaster recovery and business continuity planning, security awareness training, and asset tagging.

Concept 7 · Module 12.7

Embedded and Specialized Systems

More and more of the network is things, not computers: sensors, cameras, door locks, medical devices, and controllers. Many were never designed with security in mind.

Industrial control systems

Stuxnet (one of the Malware Case File lab's incidents) targeted SCADA (Supervisory Control and Data Acquisition) systems, a type of industrial control system (ICS) used in manufacturing, energy, and communications. SCADA was designed before anyone connected it to IT networks or the internet, so security wasn't part of the design. Separate the SCADA network from the organization's LAN.

Embedded systems and IoT

TermWhat it meansSecurity concern
Internet of Things (IoT)Technologies that connect everyday devices to the internet: cars, machines, appliances, locks, cameras, and sensorsGreatly expands the attack surface. Infected IoT devices have launched some of the largest DDoS attacks in history
Embedded systemA computer built into a device, like a smart TV, HVAC controller, medical device, or carVulnerable to timing attacks, a side-channel attack that learns from how long the system takes to respond. Power use, electromagnetic leaks, and sound can leak information too
System on Chip (SoC)A small single-board computer, like a Raspberry Pi or Arduino, that integrates the processor and peripherals. Some use an FPGA, a chip that can be reprogrammed in the fieldOften poor authentication, and many can't be patched. They require a level of implied trust
Real-time operating system (RTOS)A small OS for IoT that switches tasks quickly and focuses on timingCode injection, DoS, and priority inversion (a lower-priority task preempting a higher-priority one)

IoT devices talk over short-, medium-, and long-range methods, including cellular (4G, 5G), radio, and Zigbee, a protocol set for wireless personal area networks. An IoT search engine like Shodan shows whether a device is exposed. To secure IoT: secure the wireless network, know exactly which devices are on your network and what each does, install security software where you can, and secure the phones and apps used to control them.

VoIP

VoIP is only as secure as the network under it. Attackers want free calls, eavesdropping, or to disrupt service. Countermeasures: encrypt voice packets, use SSH to manage gateways and switches, change default passwords, use an IDS to catch attacks like ARP poisoning, use VoIP-aware firewalls, and use strong authentication against registration spoofing (rerouting a victim's incoming calls), proxy impersonation (a rogue proxy), and call hijacking (rerouting calls in transit).

Special-purpose systems

SectorExamplesRisks
MedicalPacemakers, insulin pumps, implants, and defibrillators with wireless, remote monitoring, and NFCPatient safety, leaked records, and a foothold into the hospital network
AutomotiveIn-vehicle systems that record speed, location, and brakingUnauthorized tracking, jamming, and spoofing. Use secure software design, encrypted controller communication, and firewalls
AviationFlight control and communication systems, and drones (UAVs)Hard-coded logins, insecure protocols, and backdoors. Drones face hijacking, Wi-Fi attacks, GPS spoofing, jamming, and deauthentication

Deception technologies

Deception adds a fake layer to distract attackers, learn their methods, and warn of attacks.

ToolWhat it is
HoneypotA decoy system that mimics a real server and is left exposed. Everything the attacker does there is logged
HoneynetA collection of honeypots that mimics a whole network
HoneyfileA dummy file that attracts an attacker but holds nothing real
DNS sinkholeStops hostnames for specified URLs from resolving, steering users away from malicious sites

Concept 8 · Module 13.1

Access Controls

Access control decides who gets in and what they can touch. It comes in three kinds, and AAA is the framework that ties them together.

TypeWhat it isExamples
PhysicalBarriers that prevent direct contact with systemsGuards, fences, motion detectors, laptop locks, locked doors, swipe cards, guard dogs, video cameras, mantraps (entries that stagger people through and trap intruders), alarms
LogicalHardware and software that manage access to resources and systemsEncryption, smart cards, passwords, biometrics, ACLs, protocols, firewalls, routers, IDS, and clipping levels (an allowed number of errors before an alert)
AdministrativePolicies and procedures, focused on personnel and business practicesPolicies, procedures, hiring practices, background checks, data classification, security training, and performance reviews

AAA in access control

ServiceQuestion it answersHow
AuthenticationWho are you?A username or ID, verified by something you know, something you have, or something you are
AuthorizationWhat can you do?Which resources a user can reach, which operations they can perform, and when. Often enforced with an ACL
AccountingWhat did you do?Tracks what users access, for how long, and what they change, for auditing

NetAcad compares AAA to a credit card: it identifies who can use it, sets how much they can spend, and records what they bought.

Identification and federated identity

Identification uses a unique identifier, usually a username, but possibly a PIN, smart card, or biometric, so the system can tie each action to one person. Federated identity management lets several organizations accept the same credentials, like signing in to many websites with one social login. The user gets single sign-on across the group. The cost: one compromised identity can cascade across every member, so share as little identifying information with partners as possible, and tie logins to authorized devices.

Authentication factors

FactorExamplesNotes
Something you knowPasswords, passphrases, PINsAt least eight characters, mixing upper and lowercase, numbers, and symbols. Use a different password for every system
Something you haveSmart cards, security key fobsUsually used as the second factor in 2FA
Something you arePhysiological traits (fingerprint, face, retina, DNA) and behavioral traits (voice, gait, typing rhythm)Needs a reader, software that digitizes the scan, and a database to compare against

Multi-factor authentication (MFA) uses at least two different factors, so a stolen password alone doesn't open the account. Two-factor authentication (2FA) is MFA with exactly two; the terms are often used interchangeably.

Authorization and accountability

Authorization happens automatically right after authentication. The system checks the user's attributes, like their read, copy, edit, create, and delete privileges, and applies the restrictions. An authorization policy sets the rules. A group membership policy grants access by group; an authority-level policy grants it by position. Every employee's swipe card may open the front door, but not the server room.

Accountability traces each action back to the person or process that did it, then reports the usage data for auditing or billing. It's built from technology (log files), policies and procedures (what gets logged, and how logs are reviewed and stored), data retention, media disposal, and compliance requirements, plus training people on all of it.

Concept 9 · Module 13.2

Access Control Concepts

Once you know who someone is, a model decides what they get. Knowing the models also tells you how attackers try to break them.

Zero trust

Traditionally, the network edge was the line between trusted and untrusted. In zero trust, every place an access decision is made is a perimeter. Passing one check doesn't earn trust anywhere else; you authenticate again for each resource. That contains breaches and limits an attacker's lateral movement. It has three pillars:

PillarCovers
WorkforcePeople (employees, contractors, partners, vendors) on personal or corporate devices. Only the right users on secure devices reach applications, wherever they are
WorkloadsApplications in the cloud and data centers talking to each other, like an API or container reaching a database
WorkplaceEvery device that connects, including IoT: endpoints, servers, printers, cameras, HVAC, kiosks, infusion pumps, and industrial controls

Access control models

The principle of least privilege gives users and processes only the access they need. The attack it guards against is privilege escalation: exploiting a vulnerability to gain more privilege than you should have.

ModelWho decides accessNotes
Discretionary (DAC)The data's ownerThe least restrictive. Owners set permissions (read, write, execute) for others, often with ACLs
Mandatory (MAC)The system, by comparing labelsThe strictest. Every object has a security label and every user a clearance. Used in military and mission-critical systems
Role-based (RBAC)The user's job rolePrivileges attach to roles, and people are assigned to roles. A type of non-discretionary control that suits large organizations. Can enforce DAC or MAC policies
Attribute-based (ABAC)Attributes of the user, the resource, and the environmentFor example, the time of day the access is attempted
Rule-based (also "RBAC")Rules set by network security staffRules in an ACL, like permitted IP addresses or protocols. Users can't change them
Time-based (TAC)The time and dayAccess only during set hours
Watch the acronym: role-based and rule-based access control both abbreviate to RBAC. On a quiz, read the description, not the letters. Roles and job functions mean role-based. ACL rules, IP addresses, and protocols mean rule-based.

Network access control (NAC)

NAC systems enforce policy on the people and devices trying to join the network. They:

  • Enforce access policies quickly for different operating conditions
  • Recognize and profile connected users and devices
  • Give guests secure access, often through a registration portal
  • Check a device's compliance by user type, device type, and OS before letting it on
  • Block, isolate, or repair noncompliant devices

With BYOD and IoT, nobody could check thousands of devices by hand. NAC automates it, which makes it a key part of a zero trust architecture.

Think of it like… who may enter which bailey In a castle, your rank decides which baileys you may enter: that's MAC, clearance against labels. A storehouse keeper deciding who gets a key to their own storehouse is DAC, the owner's choice. Your post, gate guard or quartermaster, deciding where you go is role-based access. Here's where the picture breaks: a castle runs one ranking system, but a network often mixes models, like role-based groups that enforce MAC labels.

Concept 10 · Module 13.3

Account Management

Every account is a key. Account management makes sure the right people hold the right keys, and that old keys stop working.

Account types and practices

Account types include administrator, user, service, and guest accounts. Never share privileged, administrator, or application accounts. Use the administrator account only to administer: browsing or reading email as admin hands any malware admin rights. Know the default accounts your OS installs, disable the ones you don't need, replace defaults, and require a password on every account.

  • On hiring, create an identity profile, register the employee's devices, and enable access. The organization is the identity provider (IdP)
  • Disable accounts that are no longer needed, and recover company data from the user's devices
  • Grant no more access than the job needs, and review access regularly
  • Restrict when users can log in (time of day) and from where (location)
Location termMeaning
GeofencingTriggers an action when a user enters or leaves a geographic boundary
GeolocationIdentifies a device by where it is
GeotaggingAdds location data to something, like a phone photo tagged with coordinates

Privileged accounts

Privileged accounts have elevated, unrestricted access, which makes them attackers' favorite target. Robust practices:

  • Identify privileged accounts and reduce how many there are
  • Enforce least privilege, and revoke access when people leave or change jobs
  • Eliminate shared accounts, shared admin credentials, and passwords that never expire
  • Store passwords securely, and change privileged passwords automatically every 30 or 60 days
  • Change embedded passwords in scripts and service accounts
  • Record privileged sessions, log all user activity, and alert on unusual behavior
  • Disable inactive privileged accounts
  • Require MFA for all administrative access
  • Put a gateway between users and sensitive assets to limit exposure to malware
Think of it like… the keys to the treasury No single retainer holds every key in a well-run castle, and opening the treasury takes two officials. If one retainer is bribed or careless, the treasury is still safe. Privileged accounts work the same way: fewer of them, nobody sharing them, MFA on every one, and every session recorded.

File access control

Permissions limit what a user or group can do to a file or folder. Giving someone a whole drive is easier, but limiting them to the folder they need is least privilege, closely tied to need to know. If their computer is infected, the malware only reaches what they could.

PermissionWhat users can do
Full ControlSee contents, change and delete existing files and folders, create new ones, and run programs
ModifyChange and delete existing files and folders, but not create new ones
Read and executeSee the contents of existing files and folders, and run programs
WriteCreate new files and folders, and change existing ones
ReadSee a folder's contents and open files and folders

A deny on a network share overrides every other permission, even for administrators. New files and folders inherit their parent folder's permissions. When data moves or is copied:

ActionSame volumeDifferent volume
MoveKeeps original permissionsInherits new permissions
CopyInherits new permissionsInherits new permissions

Account policies in Windows

In a domain, the administrator sets a domain security policy in Active Directory that applies to every domain member. A standalone PC uses Local Security Policy, opened with secpol.msc (every edition except Home).

PolicyNetAcad's example
Password policyEight characters minimum, with three of four categories (uppercase, lowercase, numbers, symbols). A password can be reused only after 24 unique passwords
Account lockout policyFive wrong attempts locks the account for 30 minutes, then the counter resets
Audit policyLogs account logon events, account management, directory service access, object access, policy changes, privilege use, process tracking, and system events

Authentication management

ToolWhat it does
Single sign-on (SSO)One set of credentials for many applications, so users only need to remember one strong password

AAA Usage and Operation

The network security policy says who can connect and what they can do. AAA is the framework that enforces it at scale, and keeps the receipts.

ComponentNetAcad's example
AuthenticationProving identity with a username and password, challenge and response, or a token card
Authorization"User 'student' can access host server XYZ using SSH only."
Accounting"User 'student' accessed host server XYZ using SSH for 15 minutes."

AAA accounting

Centralized AAA sends accounting records from every device to one place, which makes auditing simpler. When a user authenticates, a start record begins; when they finish, a stop record ends it. Records include the username, date and time, and the exact commands entered, which helps troubleshooting and provides evidence against anyone acting maliciously.

Accounting typeWhat it captures
NetworkAll PPP sessions, with packet and byte counts
ConnectionOutbound connections from the AAA client, such as SSH
EXECUser terminal sessions: username, date, start and stop times, and the access server's IP
SystemSystem-level events, like reboots or accounting being turned on or off
CommandCommands run at a given privilege level, with the time and the user
ResourceStart and stop records for authenticated connections, plus stop records for connections that failed authentication

Physical security

Two fingerprint readers

Kiriyama General is adding a fingerprint reader to the pharmacy's controlled-drug room. Vendor A's reader rarely turns away real staff but occasionally accepts the wrong finger. Vendor B's reader sometimes makes staff try twice but almost never accepts the wrong finger. Which error matters more here, and which vendor fits?

Show answer

Type II (false acceptance) matters more. Letting the wrong person into a room full of controlled drugs is a breach. Making a nurse scan twice (a Type I false rejection) is an annoyance.

Vendor B. If both vendors publish a crossover error rate (CER), compare that too: lower is better overall.

Hardening

Port 23 on a switch

Your scheduled port scan of Kaidō Freight's warehouse switches shows TCP port 23 open on three of them. What's listening, why is it a problem, and what's the fix?

Show answer

What: Telnet, which uses TCP 23.

Why it's a problem: Telnet sends the admin's username, password, and every command in plaintext. Anyone capturing traffic on that network, with Wireshark for example, can read the credentials.

Fix: enable SSH (TCP 22) for management, disable Telnet, and rescan to confirm port 23 is closed.

Wireless

The shop router's settings page

Tsukimi Sweets' Wi-Fi router shows: WPA2-PSK with AES, WPS enabled, and the admin password still set to the default. Customers and the POS terminal share the same network. What would you change?

Show answer

Disable WPS. Its PIN can be brute-forced, which hands over the network.

Change the default admin password. Defaults are published online.

Move to WPA3 if the router and devices support it. WPA2 with AES is acceptable if not.

Separate the POS terminal from customer Wi-Fi. A guest network or VLAN keeps a customer's laptop off the network that carries card payments, which matters for PCI DSS.

Resilience

How many nines?

Kiriyama General's EHR vendor offers 99.9% availability. A competitor promises 99.999% for more money. In downtime per year, what's the difference, and which would you recommend for a 24/7 hospital?

Show answer

The math: 99.9% allows about 8.8 hours of downtime a year. 99.999% allows about 5.26 minutes.

Recommendation: five nines. Nine hours without patient records in an emergency department is a patient-safety problem, not an inconvenience. The extra cost buys clustering, redundant power, and the other measures that keep a single failure from becoming an outage.

Access control

Name the model

At Kaidō Freight: (1) everyone in the Dispatch group can open the routing app, because that's their job; (2) the VPN only accepts driver logins between 5 a.m. and 10 p.m.; (3) the office manager decides who else can open the shared contracts folder she owns. Which access control model is each?

Show answer

(1) Role-based (RBAC): access follows the job role.

(2) Time-based (TAC): access depends on the time of day.

(3) Discretionary (DAC): the data's owner decides.

AAA

RADIUS or TACACS+?

Kaidō Freight has 40 Cisco switches and routers, each with its own local admin accounts. They want one central login for all network admins, and a record of every command each admin types. Local or server-based AAA, and which protocol?

Show answer

Server-based AAA. Forty devices of local accounts is hard to manage. One central server is more scalable, and removing an admin happens in one place.

TACACS+. It can authorize router commands per user or group, it encrypts the entire packet body, and command accounting logs each command with the user and time. RADIUS encrypts only the password and can't authorize individual router commands.
