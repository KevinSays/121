Scoring Vulnerabilities with CVSS

A vulnerability scan of a real network can return hundreds of findings, and nobody can fix them all at once. CVSS is how a SOC decides what to fix first. In this lab you read vector strings, score six vulnerabilities found at Bastion's clients with the official calculator, see how the same flaw matters more in one place than another, and look up two famous real ones.

Companion to Session 15 · Module 25.2–25.3 Time ~45 min Difficulty Beginner–Intermediate

Objectives

What you'll do

  • Translate a CVSS vector string into plain language
  • Choose the correct base metric values from a vulnerability description
  • Calculate base scores with the official CVSS 3.1 calculator
  • Use environmental metrics to adjust a score for one organization
  • Prioritize remediation using scores and business context
  • Look up real vulnerabilities in the National Vulnerability Database

Required resources

  • An internet connection and a web browser
  • The FIRST CVSS v3.1 calculator: first.org/cvss/calculator/3.1. Use version 3.1, the version the course teaches, even though a newer CVSS 4.0 also exists
  • The National Vulnerability Database: nvd.nist.gov
  • Session 15: CVSS for reference

Part 1

Read a vector string

Scanners and databases report CVSS as a compact vector string. Learn to read it at a glance.

  1. For each vector, write every metric out in words, such as "AV:N = network: the attacker can be anywhere on the internet."
  2. Open the calculator and click the matching value for each metric. You can also paste the vector after the calculator's address: https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:N/…. Record the base score and rating.
  3. In one sentence, describe the kind of attack the vector suggests.

Part 2

Score the findings

Bastion's quarterly vulnerability scans found six issues across its three clients. All of them are fictional. Score each one.

  1. Read each description and choose a value for every base metric. Every metric's answer is in the description, though sometimes in everyday words.
  2. Build the vector string, enter it in the calculator, and record the base score and rating.
  3. If you're unsure between two values, pick one, and note your reasoning in the last column.

V1Kiriyama General Hospital · patient portal. An attacker anywhere on the internet can send a specially crafted request to the portal's login page and run any command on the server. It works every time, no account is needed, and nobody else has to do anything. The attacker could read, change, or delete every record on the server and shut the portal down. The damage stays on the portal server.

V2Tsukimi Sweets · point-of-sale register. Someone standing at the counter can plug a USB stick into the register's exposed port and copy the card numbers it has cached. No login or special conditions are required, and no staff member has to do anything. They can read the data, but can't change it or stop the register from working. Only the register is affected.

V3Kaidō Freight · dispatch web app. Any driver with an ordinary dispatch account can post a delivery note containing a malicious script. When a dispatcher later opens that note, the script runs in the dispatcher's web browser, a different component from the vulnerable app, and can read or change a small amount of the dispatcher's session information. It doesn't affect whether anything stays available.

V4Tsukimi Sweets · guest Wi-Fi router. Anyone connected to the shop's open guest Wi-Fi can send one malformed packet that crashes the router until someone power-cycles it. It works reliably, needs no account, and no one else has to act. No data is exposed or changed. It only knocks the router offline.

V5Kiriyama General Hospital · nursing-station workstations. A user who is already logged in to a workstation with a standard, non-admin account can run a small program that gives them full administrator control of that workstation. It works reliably and needs no one else's help. The effect is limited to that workstation.

V6Kaidō Freight · VPN gateway. An attacker on the internet, with no account, can take complete control of the VPN gateway, with full ability to read, change, or shut it down. But the attack only works if they win a timing race that depends on conditions they can't control, so it usually takes many attempts. The damage stays on the gateway.

Part 3

Same flaw, different stakes

The base score describes the vulnerability. The environmental score describes what it means to you.

The flaw in V3 actually lives in a popular comment widget, and two other clients use it too. Kiriyama General Hospital uses it on its patient portal, where patient information must stay confidential and accurate. Tsukimi Sweets uses it on its public recipe blog, where nothing sensitive is stored.

  1. Load your V3 vector into the calculator.
  2. Scroll to the Environmental Score Metrics. Leave every "Modified" base metric as "Not Defined," and set only the three Security Requirements.
  3. For Kiriyama, set Confidentiality Requirement High, Integrity Requirement High, Availability Requirement Medium. Record the environmental score.
  4. For Tsukimi, set all three requirements to Low. Record the environmental score.

Part 4

Decide what to fix first

Scores inform priorities, but they don't set them on their own. This is the Prioritize and Remediate work of the vulnerability management life cycle.

  1. Rank V1–V6 in the order you'd remediate them, 1 being first.
  2. For each, note the context that moved it up or down from where its score alone would put it: internet exposure, what data is at risk, laws such as HIPAA or PCI DSS, how hard a quick workaround is.
  3. For at least one finding, name a fast compensating control you could put in place today while you wait for the real fix.

Part 5

Look up the real thing

Two of the most famous vulnerabilities of the last decade, and how CVSS scored them.

  1. On nvd.nist.gov, search for CVE-2014-0160 (Heartbleed, a flaw in the OpenSSL encryption library) and CVE-2021-44228 (Log4Shell, a flaw in the Log4j logging library used by countless Java applications).
  2. On each page, find the CVSS 3.x score from NVD (not version 2.0 or 4.0). Record the base score, rating, and vector string.
  3. Compare the two vectors metric by metric, and mark every metric where they differ.

Reflection

Write it up

Short answers, in your own words. These aren't auto-graded.

1.V1 and V6 can both give an attacker complete control from the internet. Why does V6 score lower, and should that lower score make you much less worried about it? Explain.

2.V2 scored only Medium, but it exposes credit card numbers. What did the base score not capture, and which law or standard from Session 13 makes it more urgent than its number suggests?

3.Heartbleed only exposed data (confidentiality), but Log4Shell scored a perfect 10.0. Using the metrics that differed in Part 5, explain why.

4.A manager says, "Just fix everything rated High or Critical and ignore the rest." Using your Part 3 and Part 4 results, give one reason that rule could leave the organization exposed.
