Review 2

Commonly confused

Pairs that look alike on a quiz. If you can say the difference in one sentence, you're ready for the question.

These twoThe differenceWhere
Threat vs. vulnerabilityA vulnerability is the weakness. A threat is what could exploit it. Risk is how likely and how badS1
Virus vs. worm vs. TrojanA virus needs a user to run its host file. A worm spreads on its own. A Trojan is disguised as legitimate software and doesn't replicateS1
Phishing vs. spear phishing vs. whalingMass email, a targeted person, an executive. Vishing is by phone, smishing by textS1
SYN flood vs. TCP resetA SYN flood never finishes the handshake and fills the connection table. A reset attack forges an RST to kill an existing connectionS2
DHCP spoofing vs. DHCP starvationSpoofing is a rogue server handing out false settings. Starvation exhausts the real server's address poolS3
Rogue AP vs. evil twinA rogue AP is any unauthorized AP on the network. An evil twin copies a real AP's SSID to lure clientsS3
IDS vs. IPSAn IDS watches a copy of traffic and alerts. An IPS sits inline and can blockS4
HIDS vs. HIPSThe same split on a host: a HIDS alerts, a HIPS can stop the actionS5
Signature vs. anomaly detectionSignature matches known-bad fingerprints and misses anything new. Anomaly learns normal and flags deviationsS5, S5
Standard vs. guideline vs. procedureA standard is a mandatory rule ("must"). A guideline is a recommendation ("should"). A procedure is mandatory step-by-step instructionsS6
Security onion vs. Security OnionThe analogy: an attacker peels each layer of defense in depth. The tool suite: a Linux distribution for network security monitoringS6, S5
Onion vs. artichokeThe onion assumes an attacker must get through every layer. The artichoke, for borderless networks, says pulling one leaf can expose dataS6
Type I vs. Type II errorType I is a false rejection (a real user turned away). Type II is a false acceptance (an impostor let in), usually the worse oneS7
Role-based vs. rule-based (both "RBAC")Role-based follows the job role. Rule-based follows ACL rules set by staff, like permitted IPs or protocolsS7
DAC vs. MACIn DAC, the data's owner decides. In MAC, the system compares the user's clearance with the object's labelS7
Authentication vs. authorization vs. accountingWho are you, what can you do, what did you doS7
TACACS+ vs. RADIUSTACACS+: TCP 49, mostly Cisco, encrypts the whole body, separates all three A's. RADIUS: UDP 1812/1813, open standard, encrypts only the password, combines authentication and authorizationS7

Review 3

Also in the modules

The NetAcad modules include some content that Sessions 1–5 didn't cover. The midterm can still ask about it. Each item below is a short definition taken from the module material. They're also in the flashcards and glossary, tagged "Module extras."

ModuleTermWhat it means
Module 1GraywareUnwanted applications that behave in annoying or undesirable ways. They may not carry recognizable malware, but can still track your location or push unwanted ads.
Module 1Common vulnerabilities and exposures (CVE)A public dictionary of known vulnerabilities, each with its own ID, sponsored by US-CERT and the US Department of Homeland Security.
Module 1Indicator of compromise (IOC)Evidence that a breach has happened, with details about it, such as a malware signature or a malicious domain name.
Module 1STIX and TAXIIThe structured language (STIX) and exchange method (TAXII) that CISA's Automated Indicator Sharing uses to trade threat indicators in real time.
Module 1Cloud service models (SaaS, PaaS, IaaS)Software as a Service delivers applications. Platform as a Service provides a platform to build and run applications. Infrastructure as a Service provides virtualized servers, storage, and networking.
Module 2Indicators of attack (IOA)Indicators that focus on an attacker's motivation and strategies rather than one breach, which supports a proactive defense.
Module 2Cisco Talos Intelligence GroupCisco's threat intelligence and research group. Its data feeds Cisco security appliances and helps administrators mitigate threats.
Module 3Blind vs. non-blind spoofingIn non-blind spoofing, the attacker can see the traffic between the host and the target and inspects the replies. In blind spoofing, the attacker can't see that traffic. Blind spoofing is used in DoS attacks.
Module 4Fast fluxHiding phishing and malware sites behind a quickly changing set of compromised DNS hosts, with IP addresses changing within minutes. Botnets use it to stay hidden.
Module 4Double IP fluxFast flux that also rapidly changes the authoritative name server, making the attack's source even harder to find.
Module 4Domain generation algorithm (DGA)Malware that randomly generates domain names to use as meeting points with its command-and-control servers.
Module 4Malicious iFrameHTML an attacker adds to a compromised web page so it loads content from another site, used to deliver exploit kits, spam ads, or malware.
Module 4HomoglyphsCharacters that look the same as, or nearly the same as, legitimate ones. Used to make fake links and domains look real.
Module 4Open mail relayA mail server misconfigured to relay mail for anyone. Attackers abuse it to send spam or malware in bulk.
Module 4HTTP status codesThree-digit server responses grouped by first digit: 1xx informational, 2xx success, 3xx redirection, 4xx client error, 5xx server error.
Module 5CSMA/CACarrier sense multiple access with collision avoidance: WLAN devices listen and transmit only when the channel is clear, because they can't detect collisions.
Module 5WLC and LWAPA wireless LAN controller (WLC) centralizes control and management of many access points, which then act as lightweight APs (LWAPs) instead of working on their own.
Module 6Packet filtering (stateless) firewallPermits or denies traffic by Layer 3 and Layer 4 information, without tracking connections. Usually part of a router.
Module 6Stateful firewallFilters traffic using connection information kept in a state table. Analyzes OSI Layers 3 through 5.
Module 6Application gateway (proxy) firewallFilters at OSI Layers 3, 4, 5, and 7, mostly in software.
Module 6Next-generation firewall (NGFW)Goes beyond a stateful firewall with integrated intrusion prevention and application awareness and control.
Module 6Transparent and hybrid firewallsA transparent firewall filters IP traffic between a pair of bridged interfaces. A hybrid firewall combines firewall types.
Module 6Standard vs. extended ACLsA standard ACL filters only by source IPv4 address. An extended ACL can also filter by destination, protocol, and port.
Module 6Port mirroringA switch feature that copies the traffic passing through it and sends the copy out a port where a network monitor is attached.
Module 6Cisco ESA and WSAThe Email Security Appliance and Web Security Appliance: Cisco devices that filter email and web traffic using Talos threat intelligence.
Module 6Layer 3 VPNs: GRE, IPsec, MPLSGRE and IPsec make point-to-point site connections. MPLS can connect many sites to each other.
Module 7Master File Table (MFT)The NTFS table that holds the location of every file and directory on a partition, plus attributes like security information and timestamps. The partition boot sector points to it.
Module 7Session Manager Subsystem (SMSS)The Windows boot component that reads the registry to create the user environment, start Winlogon, and prepare each user's desktop.
Module 7Server Message Block (SMB)The protocol Windows uses to share files and other resources on remote hosts.
Module 7nslookupA command that tests DNS by looking up a name, such as nslookup cisco.com.
Module 7Windows Management Instrumentation (WMI)A Windows feature for managing remote computers: reading component information and statistics and monitoring their health.
Module 7AppLockerA Windows feature that restricts which files users or groups are allowed to run.
Module 8Master Boot Record (MBR)Located in the first sector of a partitioned disk, it stores the information about how the file system is organized.
Module 9Endpoint detection and response (EDR)A security solution that continuously monitors, collects, and analyzes data from an endpoint and responds to threats it detects.
Module 9Data loss prevention (DLP)Tools that centrally make sure sensitive data isn't lost, misused, or accessed by unauthorized users.
Module 9TCP WrappersA rule-based access control and logging system for Linux. One example of a host-based firewall.
Module 9XProtect and GatekeepermacOS protections. XProtect blocks malware using signatures. Gatekeeper only allows signed software from Apple-notarized developers.

Worked examples

Sessions 1, 4, 5

The invoice attachment

A Kaidō Freight accounts clerk opens an emailed "invoice" that installs software, which then starts copying itself to other PCs on the office network without anyone clicking anything. Name the social engineering technique, the two malware behaviors, and two controls that would have helped.

Show answer

Technique: phishing, a fake email from a trusted-looking source (Session 1).

Malware behavior: it arrived like a Trojan, disguised as a legitimate file the user chose to open. It then spread like a worm, copying itself across the network with no user action (Session 1).

Controls: security awareness training against phishing. On the hosts, antimalware and a HIPS to catch and block the behavior (Session 5). On the network, an IPS to block the spreading traffic inline (Session 4).

Sessions 3, 6, 7

The second "TsukimiWiFi"

A Tsukimi Sweets customer reports two networks named "TsukimiWiFi," one with a stronger signal. After joining it, they were sent to a fake login page. What attack is this, which CIA leg is at risk, and what would stop it?

Show answer

Attack: an evil twin, copying the real SSID so clients connect to the attacker, who can then run a man-in-the-middle attack (Session 3).

CIA leg: confidentiality. The fake login page is there to capture credentials.

What stops it: mutual authentication, where the client verifies the network as well as the network verifying the client (Session 6, Session 7). Enterprise authentication with 802.1X and EAP supports that (Session 3).

Sessions 4, 5, 6, 7

The 3 a.m. logins

Kiriyama General's syslog server shows dozens of failed SSH logins to a Linux imaging server at 3 a.m., then one success for an account that belongs to a radiologist who works days. Where would you look to confirm what happened, and which controls would have limited the damage?

Show answer

Look at: the server's authentication log in /var/log (Session 5) and the central syslog copy, with timestamps you can trust because every device uses NTP (Session 4). Compare the server against its baseline for new accounts or services (Session 6).

This looks like password guessing that succeeded: a confidentiality breach of patient images.

Controls: an account lockout policy and MFA would have stopped the guessing. A time-based rule could block day-shift accounts at 3 a.m. Least privilege limits what the stolen account can reach (Session 7).

Sessions 6, 7

Place the defenses

Kaidō Freight is redesigning its network. Its public website, its internal file server, and the drivers' VPN all currently sit on one flat network. Using defense in depth, where should each go, and what one principle should govern access to the file server?

Show answer

Website: in a DMZ, so outsiders reach it without touching the internal network (Session 7).

File server: on the private LAN, ideally in its own VLAN, behind the edge router, firewall, and internal router layers (Session 6).

Drivers on VPN: treat them as the artichoke's exposed leaves. Authenticate every connection, and don't trust them more just because they're "inside." That's zero trust.

Principle: least privilege. Each user gets only the folders their job needs.
