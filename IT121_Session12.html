Overview

What Session 12 covers

Module 19 looks at the network from a monitoring point of view: how common protocols behave, how threat actors misuse them, and how technologies such as NAT, encryption, Tor, and load balancing make that misuse harder to see. Concept 1 · Module 19.1

Monitoring Common Protocols

The protocols every network needs are the ones attackers like best, because their traffic is everywhere and rarely blocked.

Syslog and NTP

Syslog sends event messages from devices to a central syslog server (UDP port 514). Those logs are an analyst's evidence, so attackers go after them. They may delete or alter log entries, or try to stop logging, to hide what they did. Sending logs to a separate, protected syslog server means an attacker who controls one device can't quietly edit its history.

Network Time Protocol (NTP) keeps device clocks synchronized (UDP port 123), using a hierarchy of time sources. Accurate time is what lets an analyst line up events from many devices into one timeline. If clocks disagree, correlation falls apart. Attackers can target NTP to corrupt timestamps and muddy the trail, and they also abuse misconfigured NTP servers to amplify DDoS attacks.

DNS

Every host uses DNS, and most firewalls let it out, which makes it attractive for malware. It's used to:

  • Reach command-and-control (CnC) servers. Malware looks up a domain the attacker controls, and the DNS answers carry instructions.
  • Exfiltrate data. Stolen data is encoded into the names being looked up. This is DNS tunneling. Each query reaches the attacker's own DNS server, which collects the pieces.

Signs to look for: many lookups to one domain, unusually long or random-looking subdomains, lots of uncommon record types such as TXT, and DNS traffic from a host far above its normal volume. DNS logs and DNS proxy services make these patterns visible.

HTTP and HTTPS

Plain HTTP sends everything in clear text, so it can be read and altered in transit, and it's also how a lot of malware arrives. Attacks to know:

Malicious iFrameAn iFrame (inline frame) is an HTML element that lets a page load content from another source. Attackers who compromise a legitimate site insert a hidden iFrame that loads malicious content from their own server. The visitor sees the normal site.
HTTP 302 cushioningUses chains of HTTP 302 "Found" redirects to bounce a browser through several sites before it lands on a malicious one. This hides where the attack really comes from.
Domain shadowingAn attacker steals the credentials for a legitimate domain and creates many subdomains under it to host malicious content. The subdomains inherit the parent domain's good reputation.

HTTPS fixes HTTP's privacy problem with end-to-end encryption, and that's exactly what makes monitoring hard. An IPS can see the connection, but not the content. Session 11 covered how SOCs respond with TLS decryption, metadata, and endpoint monitoring.

Email protocols

ProtocolPortJob
SMTPTCP 25Sends email from a client to a server and between mail servers in different domains
POP3TCP 110Downloads mail from the server to the client, usually removing it from the server
IMAPTCP 143Retrieves mail while keeping it on the server, synchronized across devices

Email is a leading way to deliver phishing and malware, and outbound SMTP can carry stolen data out. Webmail runs over HTTPS, so its content is hidden from network inspection. That's one reason organizations filter email with a dedicated security appliance.

ICMP

ICMP carries network diagnostics: ping, unreachable messages, and time exceeded. Attackers use it for reconnaissance (ping sweeps to find live hosts, and mapping the network), for DoS floods, and for ICMP tunneling, hiding data in the payload of echo messages to sneak it out. Rather than block ICMP entirely, which breaks troubleshooting, filter it. On the outside interface, permit only the inbound types internal users need, such as echo reply, source quench, and destination unreachable, and deny the rest.

Syslog, NTP, and NetFlow as security services are in Session 4. ICMP filtering with ACLs is in Session 9. Phishing and email-borne malware are in Session 1.

Concept 2 · Module 19.2

Security Technologies

Many of the tools that protect a network also take away part of the analyst's view. Know which ones, and what they hide.

ACLsACLs can give a false sense of security. An attacker who learns which ports are allowed can send traffic that fits the rules, such as tunneling over DNS or HTTPS. On the other hand, logging denied packets tells you who is probing.
NAT and PATHide internal addresses behind one or a few public addresses. An outside log entry shows the public address, not which inside host was responsible. To find the host, you need the router's translation logs, with accurate timestamps. This also complicates NetFlow, because flows are one-way records keyed on addresses and ports that NAT rewrites.
Encryption, encapsulation, and tunnelingVPNs and HTTPS keep data private, and also hide the payload from IDS and IPS. Tunneling wraps one protocol inside another, so malicious traffic can travel inside an allowed protocol.
Peer-to-peer (P2P)Hosts connect directly to each other instead of through a server: file sharing, processor sharing, instant messaging. P2P file sharing can spread malware and leak data, and its traffic is hard to control.
TorA network of volunteer P2P hosts acting as routers, letting users browse anonymously. Traffic is wrapped in layers of encryption and relayed through several hosts. Useful for privacy, and also for threat actors hiding their location and CnC traffic.
Load balancingSpreads traffic across several servers or paths. One name can resolve to many addresses, so traffic for one service is spread across many IPs. A load balancing manager (LBM) sends probe messages to check server health, and those probes can look like suspicious traffic.

How Tor hides the path

Before sending, the Tor client wraps the message in three layers of encryption, one for each relay on its chosen path. Each relay strips off only its own layer, which reveals only the next hop. The entry relay knows who you are but not where you're going. The exit relay knows the destination but not who you are. No single relay knows both.

For a defender, Tor traffic from inside the network is a red flag in most organizations. It may be a user dodging policy, or malware hiding its CnC. Lists of known Tor relays let you detect or block it.

Tor's trick is easier to hold onto with a picture, and the castle town already ran a network that worked a lot like it.

Think of it like… the relay couriers of the Tōkaidō Letters along the Tōkaidō road traveled by relay: a courier ran to the next post station and handed the bundle to a fresh runner, who ran it to the next. Now imagine the sender seals the letter in three nested envelopes. The first station's clerk opens the outer one, which says only "take this to the second station." The second opens the next, which says "take this to the third." Only the third envelope names the real recipient. The first clerk knows who sent it but not where it's going. The last knows where it's going but not who sent it. That's Tor. For the magistrate's inspectors, that's the problem: no single station's records connect sender and recipient.

Concept 3 · Module 20.1

Types of Security Data

Four kinds of data, from a one-line alert to every byte on the wire.

Alert dataMessages generated by an IDS or IPS when traffic violates a rule or matches the signature of a known exploit. Tools such as Snort and Suricata produce it, and Security Onion collects it. An alert is a lead to investigate, not proof.
Session and transaction dataSession data is a record of a conversation between two hosts: its 5-tuple (source IP, source port, destination IP, destination port, protocol), plus when it started, how long it lasted, and how many bytes moved. Transaction data is the individual messages exchanged within a session, such as the HTTP requests and responses a web server logs.
Full packet capturesThe most detailed data: every packet, including the payload, so you can see the actual content of the conversation (emails, web pages, files). Captured with tools like tcpdump and viewed in Wireshark. It costs a lot of storage, so it's usually kept only briefly or for selected traffic.
Statistical dataCreated by analyzing other network data, to describe normal behavior and predict or spot deviations. It's how you build a baseline. Tools such as Cisco Cognitive Intelligence use statistical analysis to find threats already inside the network, including ones that arrived through unmonitored channels like removable media.

Deciding which data to collect is a trade-off between detail and cost. Packet captures answer almost any question but fill disks fast. Session records are tiny, but can't show you what was said. The castle town's post stations faced the same choice.

Think of it like… the post station's ledger Every parcel that passes the post station goes into the ledger: who sent it, to whom, the hour, and the weight. The ledger is cheap to keep for years, and it shows patterns: a merchant who suddenly sends heavy parcels every night to a stranger in another province. But it can't say what was in them. To know that, an inspector has to open and copy every letter. That's thorough, but it takes a warehouse to store the copies. The ledger is session data (and NetFlow, later in this session). The copied letters are full packet capture. The inspector's yearly notes on what "normal" traffic looks like are statistical data.

Concept 4 · Module 20.2

End Device Logs

Hosts and servers write down what happens to them. Know where to look and how to read an entry.

Host logs and Windows event logs

A host-based intrusion detection system (HIDS) runs on the host itself and records local events. Windows keeps its events in several logs, reviewed with Event Viewer:

Windows logRecords
ApplicationEvents logged by applications
SystemEvents logged by Windows system components, such as drivers and services
SecuritySecurity events: login attempts, and file or object management and access
SetupEvents from installing software, including Windows updates

Every Windows event has one of five event types:

ErrorA significant problem, such as loss of data or functionality
WarningNot necessarily significant now, but may indicate a future problem
InformationThe successful operation of an application, driver, or service
Success AuditAn audited security access attempt that succeeded, such as a successful login
Failure AuditAn audited security access attempt that failed, such as a failed login

A burst of Failure Audit login events followed by a Success Audit for the same account is a classic sign of a password-guessing attack that worked.

Syslog messages

Linux hosts and network devices use syslog. A syslog message has three parts: PRI (priority, combining the facility, which identifies the source such as the kernel, mail, or authentication, and the severity), the HEADER (timestamp and hostname), and the MSG (the text of the message). Severity runs from 0 to 7. The lower the number, the more urgent:

LevelNameMeaning
0EmergencySystem is unusable
1AlertImmediate action needed
2CriticalCritical condition
3ErrorError condition
4WarningWarning condition
5NoticeNormal but significant condition
6InformationalInformational message
7DebuggingDebug-level message

A common memory aid, from 0 to 7: "Every Awesome Cisco Engineer Will Need Ice-cream Daily."

Server logs

Servers keep their own logs, and those are essential evidence for attacks on the server. DNS servers log queries and responses. Web servers log every request. Apache's access log uses the Common Log Format, one line per request:

203.0.113.45 - - [03/Mar/2025:14:02:11 -0500] "GET /track.php?id=1042 HTTP/1.1" 200 5120
FieldIn the example
Client IP address203.0.113.45
Identity and user ID- - (a hyphen means the field is empty)
Timestamp[03/Mar/2025:14:02:11 -0500], with the time zone offset
Request"GET /track.php?id=1042 HTTP/1.1": method, resource, protocol
Status code200 (success; 404 is not found, 401/403 are refused, 500 is a server error)
Size5120 bytes returned

Microsoft's IIS web server uses a different layout, the W3C Extended Log Format, but records similar fields.

SIEM and log collection

Logs scattered across hundreds of devices are hard to use. A security information and event management (SIEM) system collects them in one place and provides real-time reporting and long-term analysis of security events. Its core functions:

AggregationCollects logs from many sources and consolidates duplicate events
CorrelationLinks related events from different systems to spot attacks no single log would show
Forensic analysisSearches logs and event records to investigate an incident after the fact
ReportingDashboards and reports for monitoring and for compliance

Popular SIEM platforms include Splunk and Security Onion with ELK (Elasticsearch, Logstash, Kibana). Hosts often run a small agent that forwards their logs to the SIEM.

Concept 5 · Module 20.3

Network Logs

Network devices and services see traffic that no single host does. Each one gives a different slice of it.

tcpdump

tcpdump is a command-line packet analyzer. It can display packets in real time, or write them to a file (with -w) in the pcap format that Wireshark and other tools can open later. It captures full detail, including content, so it's a source of full packet captures.

$ sudo tcpdump -i eth0 -w capture.pcap port 53
$ tcpdump -r capture.pcap

NetFlow

NetFlow collects metadata about each flow, not the packets' content. A flow is a one-way stream of packets sharing the same 5-tuple. Each flow record holds the addresses, ports, and protocol, plus start and end times and packet and byte counts. It's the post station ledger: cheap to keep for a long time, and good at revealing who talked to whom and how much, without the content. Flow records go to a collector and can be viewed with tools such as nfdump and FlowViewer.

Application visibility and control

Port numbers no longer reliably tell you which application is running, since so much now runs over port 443. Cisco Application Visibility and Control (AVC) identifies applications by examining traffic more deeply. It has four modules:

Application RecognitionCisco's Next Generation Network-Based Application Recognition (NBAR2) discovers and classifies applications, more than 1000 of them.
Metrics CollectionFlexible NetFlow exports traffic metrics for each application.
Management and ReportingCollects, analyzes, and reports on the application data.
ControlUses QoS to prioritize, limit, or block applications.

Content filter and proxy logs

Content filter devices log what they block and why. Cisco's Email Security Appliance (ESA) logs messages filtered for spam and malware, and its Web Security Appliance (WSA) logs web traffic it filters. Proxy servers sit between users and the internet and make requests on their behalf, so their logs record every request: which user or host, the URL, the time, the result, and the browser's user agent. A DNS proxy service, such as Cisco Umbrella, logs and filters DNS lookups, which helps reveal malware that uses DNS.

Logs from Cisco devices

Cisco routers, switches, and firewalls send syslog messages in a standard format:

Next-generation firewalls and IPS

Next-generation firewall and IPS devices, such as Cisco Firepower, generate several kinds of events an analyst sees in their management console:

Connection eventsSession data about the connections the device sees
Intrusion eventsGenerated when traffic matches an exploit signature or violates policy
Host or endpoint eventsInformation about devices discovered on the network
Network discovery eventsChanges detected on the network, such as a new host or application
NetFlow eventsFlow data the device collects or exports
Putting it together. No single source tells the whole story. An intrusion alert says something matched a signature. NetFlow says how much data that host sent and where. The proxy log names the URL. The Windows security log shows who was logged in. Packet capture shows the actual content, if you kept it. Correlating them, with timestamps that agree thanks to NTP, is what a SIEM and an analyst do. Session 13 covers how analysts evaluate the alerts.

Applied

Worked examples

Real-ish cases from Bastion's clients. Think each one through before you expand the answer.

DNS

The chatty dispatch PC

Bastion's DNS logs show a dispatch PC at Kaidō Freight making about 9,000 lookups an hour, all to subdomains of one unfamiliar domain. Each subdomain is a long string like Z3Vlc3Qtbm90ZXM0Mg.b19.tun.example.net, and most queries ask for TXT records. Other PCs make a few hundred lookups an hour. What's likely going on?

Show answer

This looks like DNS tunneling. The long encoded labels carry chunks of data (here, Base64), the short label looks like a sequence number, and every query goes to the attacker's name server. The TXT answers can carry commands back, so the same channel may be CnC.

Next steps: isolate the PC, block the domain at the DNS proxy, find out what data the host could reach, and check whether any other hosts are querying that domain.

NAT and NTP

Which PC was it?

An outside organization reports that Kiriyama General Hospital's public address 198.51.100.20 attacked one of its servers at 02:14 UTC. Hundreds of hospital devices share that address through PAT. What do you need to identify the inside host, and what could stop you?

Show answer

Need: the edge router's or firewall's NAT/PAT translation logs for that time. They map the public address and source port to an inside address. The report should also include the source port, and the inside address can then be tied to a device through DHCP logs.

What could stop you: translation logging not turned on, logs not kept long enough, or clocks out of sync. If the router's time is off by even a minute, you may match the wrong connection. That's why every device should use NTP.

Windows logs

Forty failures and a success

On a Tsukimi Sweets office server, the Windows Security log shows 40 Failure Audit logon events for the account admin within two minutes, all from one workstation's address, then a Success Audit logon for admin from the same address. What happened, and what do you do?

Show answer

A password-guessing attack (brute force or dictionary) that succeeded. The failures are in the Security log because logon attempts are audited security events.

Do: treat the account as compromised. Disable it or reset its password, investigate the source workstation for malware, review what the account did after logging in, and add account lockout so repeated failures stop being possible.

Server logs

Reading the shop's access log

Tsukimi Sweets' web server log contains hundreds of lines like these, from one address, in about a minute:

192.0.2.77 - - [03/Mar/2025:09:41:02 -0500] "GET /admin/ HTTP/1.1" 404 312
192.0.2.77 - - [03/Mar/2025:09:41:02 -0500] "GET /backup.zip HTTP/1.1" 404 312
192.0.2.77 - - [03/Mar/2025:09:41:03 -0500] "GET /wp-login.php HTTP/1.1" 404 312
192.0.2.77 - - [03/Mar/2025:09:41:03 -0500] "GET /.git/config HTTP/1.1" 404 312

What is this, and which line would worry you most if it appeared?

Show answer

An automated scan: one client rapidly requesting common admin pages and sensitive files to see what exists. The 404 status codes mean none of these were found, so so far nothing was exposed.

Worry: any of these requests with a 200 status and a large size, such as /backup.zip returning 200 with megabytes of data. That would mean a sensitive file was actually downloaded.

Types of data

Did data leave?

An IPS alert says a Kaidō Freight file server matched a signature for a known data-stealing malware family. The manager asks two questions: "Did data leave?" and "What exactly was taken?" Which type of security data answers each?

Show answer

"Did data leave?" Session data, such as NetFlow: look for flows from the file server to outside addresses and their byte counts. A large outbound transfer after the alert is a strong sign.

"What was taken?" Only a full packet capture holds the content, and only if one was running and the traffic wasn't encrypted. Otherwise, the answer has to come from the host: file access logs and an investigation of the server.

Security technologies

The connection that goes nowhere

Firewall logs show a workstation at Kiriyama General Hospital making repeated encrypted connections to a changing set of outside addresses. A threat intelligence feed identifies every one of them as a known Tor entry relay. The user says they "just browse normally." Why is this a concern even though nothing was blocked?

Show answer

Tor hides the real destination, so the hospital can't tell where the traffic is going or what's in it. Either a user is deliberately getting around policy and monitoring, or malware is using Tor for CnC. Many malware families do.

Do: check the workstation for malware and for an installed Tor client, and consider blocking known Tor relays at the edge, which policy at most organizations, especially in healthcare, would support.
