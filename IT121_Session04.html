IT121 · Session 4

Network Security Infrastructure & The Windows Operating System

Sessions 2 and 3 covered how the network gets attacked. This session flips to defense: the devices and services that stand between an attacker and the network, then a shift to the endpoint itself — how Windows is built, how it's administered, and how it's kept secure, since most of what a Tier-1 analyst investigates day to day is happening on a Windows host.

Overview

What Session 4 covers

Two modules: first, the network security infrastructure itself — the specialized devices that sit in front of traffic, and the services that support them. Then Windows: where it came from, how it's put together internally, the tools an analyst uses to configure and monitor it, and the settings that keep it from being the easiest way into a network.

  • Explain how specialized devices — firewalls, IPS, VPN, NAC, and dedicated security appliances — enhance network security
  • Explain how services like AAA, logging, and time synchronization enhance network security
  • Describe the history of the Windows operating system, from DOS-based to NT-based releases
  • Explain Windows architecture — kernel vs. user mode, processes, the file system, and the registry
  • Use Windows administrative tools to configure, monitor, and manage system resources
  • Explain how Windows is kept secure — updates, local security policy, and built-in protections

Concept 1 · Module 6.1

Security Devices

A specialized device does one job at the network boundary — filtering, detecting, tunneling, or gatekeeping — better than a general-purpose router or switch would.

DeviceWhat it does
FirewallFilters traffic between a trusted network and an untrusted one, based on a defined rule set — the baseline perimeter control
Intrusion Prevention System (IPS)Sits inline with traffic and can actively block a detected threat in real time, not just alert on it
Intrusion Detection System (IDS)Monitors a copy of traffic out-of-band and alerts on suspicious activity, but doesn't sit inline and can't block it directly
VPN concentrator / VPN-enabled routerTerminates encrypted tunnels from remote users or sites, extending the protected network over an untrusted one
Network Access Control (NAC)Checks a device's security posture (patch level, antivirus status) before granting it network access at all
Specialized security appliancesPurpose-built devices for one traffic type — e.g. an email security appliance filtering spam and phishing, or a web security appliance filtering malicious sites
IDS vs. IPS is a placement question as much as a naming one. IDS watches a mirrored copy of traffic — it can alert but never block, and a false positive costs nothing but an alert. IPS sits directly in the traffic path — it can block in real time, but a false positive can drop legitimate traffic.

Concept 2 · Module 6.2

Security Services

Devices filter and block; services do the supporting work that makes filtering, blocking, and investigating possible in the first place.

ServiceWhat it does
AAA (Authentication, Authorization, Accounting)Verifies identity, controls what an authenticated user is allowed to do, and logs what they actually did — usually via RADIUS or TACACS+
SyslogCentralizes log messages from routers, switches, servers, and security devices into one place, instead of leaving them scattered on each device
NTP (Network Time Protocol)Synchronizes clocks across every device on the network — without it, log timestamps from different devices can't be lined up to reconstruct an incident
SNMP (Simple Network Management Protocol)Lets a management station poll and monitor the health and status of network devices remotely
NetFlowCollects metadata about traffic flows crossing a device — who talked to whom, how much, how often — without capturing full packet contents
NTP is easy to underrate. A firewall log timestamped three seconds off from a server log sounds trivial — until an analyst is trying to prove which event happened first during an incident, and the timeline doesn't line up because the clocks never agreed.

Concept 3 · Module 7.1

Windows History

Two family lines matter: the old DOS-based consumer releases, and the NT-based line that eventually replaced them and is what every modern Windows box actually runs.

LineExamplesNotes
DOS-basedWindows 3.1, 95, 98, MeRan on top of MS-DOS rather than replacing it — no real memory protection between processes, which made the whole system fragile and insecure by modern standards
NT-basedWindows NT, 2000, XP, Vista, 7, 8, 10, 11Built on a genuinely new kernel with real security features — user accounts, permissions, memory protection. Every current release is NT-based
Client vs. server editions split off the same NT kernel: client editions (7, 10, 11) target a single user on a workstation; server editions (Windows Server) add roles like Active Directory Domain Services, DNS, and DHCP for managing a whole network of clients.

Concept 4 · Module 7.2

Windows Architecture and Operations

What actually happens under the hood — the layers between hardware and the programs a user runs, plus the two places Windows stores almost everything about itself.

ConceptWhat it is
User mode / Kernel modeTwo privilege levels — user mode applications can't directly touch hardware or other processes' memory; kernel mode code can, which is why a kernel-mode exploit is far more dangerous than a user-mode one
Process / ThreadA process is a running program with its own memory space; a thread is a unit of execution within that process — a process can have many threads
Windows RegistryA hierarchical database of configuration settings for the OS and installed applications, organized into root keys such as HKEY_LOCAL_MACHINE and HKEY_CURRENT_USER
NTFSThe standard modern Windows file system — supports file-level permissions, encryption, and journaling (which helps recover from a crash without corrupting the file system)
NTFS permissions and the registry are also where a lot of Windows-based attacks and persistence techniques live — worth remembering when Module 27's forensics content revisits Windows artifacts later in the term.

Concept 5 · Module 7.3

Windows Configuration and Monitoring

The built-in tools an analyst reaches for first — no third-party software required, all already on the box.

ToolWhat it's for
Task ManagerReal-time view of running processes, resource usage, and startup programs — the fastest way to spot something consuming CPU or network it shouldn't
Event ViewerBrowses the Windows event logs (Application, Security, System) — the primary source of historical evidence for what happened on a host
Microsoft Management Console (MMC)A framework that hosts administrative snap-ins (like Computer Management, Services, or Group Policy) in one customizable window
Services (services.msc)Lists every Windows service, its status, and its startup type — used to start, stop, or disable background processes
Windows PowerShellA scripting shell and language for administration and automation — far more capable than the legacy Command Prompt
netstatLists active network connections and listening ports from the command line — a first move when checking what a host is actually talking to
Task SchedulerRuns programs or scripts automatically on a schedule or trigger — also a common persistence mechanism attackers abuse
netstat and Task Scheduler both cut two ways. They're legitimate administrative tools, but they're also exactly what an analyst checks when investigating a compromise — an unexpected listening port or an unfamiliar scheduled task is a classic signal something else is running on the box.

Concept 6 · Module 7.4

Windows Security

Windows ships with real, functional security features — the trouble is usually a machine where they've been left off, out of date, or misconfigured, not a machine that lacks them entirely.

FeatureWhat it protects against
Windows UpdatePatches known vulnerabilities — an unpatched system is exploitable by attacks that a patched one is already immune to
User Account Control (UAC)Prompts for confirmation before an action that requires administrator privileges, limiting the damage malware can do while running under a standard user account
Windows Defender (Windows Security)Built-in antivirus and antimalware protection, enabled by default
Windows FirewallHost-based firewall filtering inbound and outbound traffic on the machine itself, independent of any network firewall
Local Security PolicyConfigures account and audit policies on a single machine — password requirements, lockout thresholds, and what gets logged
BitLockerFull-disk encryption — protects data at rest if a device is lost or stolen, since the drive is unreadable without the key
UAC is a permission boundary, not a malware scanner. It doesn't decide whether an action is malicious — only whether it needs elevated privilege to run. Malware that never needs admin rights can still do plenty of damage without ever triggering a prompt.

Worked examples

Security devices

IDS or IPS?

Scenario A: a device receives a mirrored copy of network traffic from a switch's SPAN port, analyzes it, and sends an alert to the SOC when it spots something suspicious — but the traffic itself was never touched. Scenario B: a device sits directly in the path between the internet and the internal network, and when it spots the same suspicious pattern, the traffic never makes it through at all.

Show answer

Scenario A: IDS — out-of-band, alert-only, working from a copy of traffic.

Scenario B: IPS — inline, able to block traffic in real time because it sits directly in the path.

Security services

The timeline that didn't add up

An analyst is reconstructing an incident from three devices' logs: a firewall, a switch, and a server. The firewall log says an alert fired at 14:02:03. The server log shows the matching process starting at 14:01:58 — five seconds before the firewall event that supposedly triggered it. Nothing else about the logs looks wrong.

Show answer

Most likely cause: the devices' clocks aren't synchronized — a missing or misconfigured NTP service. Once every device shares the same time source, the true order of events becomes reconstructable again.

Windows history

DOS-based or NT-based?

An IT department decommissioning old lab equipment finds one machine still running Windows 98, and another still running Windows XP. They want to know which one is the bigger security liability architecturally, not just because it's old.

Show answer

Windows 98 is the DOS-based line — it lacks the memory protection and permission model the NT-based line introduced. Windows XP is NT-based, so architecturally it's the more defensible of the two, even though both are long past end-of-support and need to be retired.

Windows administration

Which tool for which question?

An analyst has four questions: (1) Is this process using 90% of the CPU right now? (2) What security events happened on this box over the last three days? (3) Is anything listening on a port I don't recognize? (4) Is there a task scheduled to run at 3 a.m. that nobody on the team remembers creating?

Show answer

(1) Task Manager. (2) Event Viewer. (3) netstat. (4) Task Scheduler.

Windows security

UAC didn't stop it — was that a bug?

A user's machine gets infected with malware that quietly logs their keystrokes and sends them out over the network. No UAC prompt ever appeared. The user assumes UAC must be broken.

Show answer

Not a bug. UAC only prompts when an action requires administrator privileges. Keylogging and exfiltrating data over the network don't require elevation — a standard user account already has enough access to do both. UAC is a privilege boundary, not a malware detector.
